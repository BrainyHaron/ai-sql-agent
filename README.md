AI SQL Аналитик для PostgreSQL

Локальный AI-агент, преобразующий запросы на естественном языке (русский/английский) в SQL-запросы к базе данных PostgreSQL с последующим выполнением и интерпретацией результатов.

Работает **полностью автономно** на локальной нейросети Ollama (модель Qwen 2.5 Coder 7B), не требует API-ключей и интернета после первоначальной загрузки модели.

Возможности

- Понимание запросов на **русском и английском языках**

- Автоматическая генерация SQL-запросов на основе схемы БД

- Выполнение SQL и отображение результатов в виде таблицы

- Генерация текстового резюме результата на русском языке

- **Многоуровневая безопасность**: агент работает только в режиме READ-ONLY

- Вежливый отказ при попытках выполнить деструктивные операции (INSERT, UPDATE, DELETE, DROP и др.)

- Ограничение размера результата через `LIMIT 20`

- Таймаут на выполнение запросов

Поток данных

1. Пользователь вводит запрос на естественном языке в веб-интерфейс

2. **Проверка намерения** — система анализирует запрос на наличие деструктивных операций

3. **Генерация SQL** — LLM (Qwen 2.5 Coder) формирует SQL-запрос на основе схемы БД

4. **Валидация SQL** — проверка на наличие запрещённых операций (INSERT, UPDATE, DELETE и т.д.)

5. **Выполнение запроса** — SQL выполняется через read-only пользователя БД

6. **Генерация резюме** — LLM формирует текстовое объяснение результата на русском языке

7. **Отображение** — пользователь видит SQL-запрос, таблицу результатов и резюме



Безопасность

Реализована **многоуровневая защита** от несанкционированных изменений в БД:



Уровень 1: Анализ намерения пользователя

Проверка исходного запроса на наличие деструктивных операций на русском и английском языках:

- `удали`, `delete`, `drop`, `обнови`, `update`, `добавь`, `insert`, `создай`, `create` и др.



Уровень 2: Валидация SQL-запроса

Проверка сгенерированного SQL перед выполнением на наличие запрещённых ключевых слов:

- `INSERT`, `UPDATE`, `DELETE`, `DROP`, `CREATE`, `ALTER`, `TRUNCATE`, `GRANT`, `REVOKE`, `EXEC`, `EXECUTE`



Уровень 3: Read-only пользователь БД

Агент подключается к PostgreSQL под пользователем `readonly_user`, которому на уровне БД разрешена **только операция SELECT**. Даже если каким-то образом опасный SQL будет сгенерирован и пройдёт валидатор, БД его отклонит.



Уровень 4: Системный промпт

Явные инструкции в промпте модели запрещают генерировать деструктивные запросы.



Дополнительные меры

- Ограничение размера результата: `LIMIT 20`

- Таймаут на выполнение запросов (30 секунд)

- Секреты не хранятся в коде (используются переменные окружения в docker-compose)



Тестовая база данных

Используется открытая база **Chinook** — имитирует цифровой музыкальный магазин (аналог iTunes/Spotify).



Схема БД (11 таблиц)

- *`artist`** — исполнители (artist_id, name)

- *`album`** — альбомы (album_id, title, artist_id)

- *`track`** — треки (track_id, name, album_id, genre_id, unit_price и др.)

- *`genre`** — жанры (genre_id, name)

- *`media_type`** — типы медиа (media_type_id, name)

- *`playlist`** — плейлисты (playlist_id, name)

- *`playlist_track`** — связь плейлистов и треков

- *`customer`** — клиенты (customer_id, first_name, last_name, country, email и др.)

- *`employee`** — сотрудники (employee_id, first_name, last_name, title и др.)

- *`invoice`** — счета/заказы (invoice_id, customer_id, invoice_date, total и др.)

- *`invoice_line`** — позиции счетов (invoice_line_id, invoice_id, track_id, unit_price, quantity)



Объём данных

- 275 исполнителей

- 347 альбомов

- 3503 трека

- 59 клиентов из разных стран

- 414 счетов с позициями

Инструкция по запуску



Предварительные требования

- **Docker Desktop** версии 20.10 или выше (([https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)))

- Минимум **8 ГБ свободной RAM** (для работы модели Qwen 2.5 Coder 7B)

- Минимум **10 ГБ свободного дискового пространства** (для модели и образов)

- Стабильное интернет-соединение для первичной загрузки (только при первом запуске)



Шаги запуска

1. **Клонируйте репозиторий** или распакуйте архив:

   ```bash

   git clone <(https://github.com/BrainyHaron/ai-sql-agent)>

   cd ai-sql-agent

   ```

2. **Запустите проект одной командой**:

   ```bash

   docker-compose up --build

   ```

   При первом запуске:

   - Скачаются Docker-образы PostgreSQL, Python и Ollama (~1-2 ГБ)

   - Автоматически скачается модель `qwen2.5-coder:7b` (~4.5 ГБ)

   - Создастся и наполнится база данных Chinook

   

   **Общее время первого запуска: 5-15 минут** (зависит от скорости интернета).

   При повторных запусках — 30-60 секунд.

3. **Дождитесь сообщения в логах**:

   ```

   You can now view your Streamlit app in your browser.

   URL: [http://0.0.0.0:8501](http://0.0.0.0:8501)

   ```

4. **Откройте браузер** и перейдите по адресу:

   ```

   [http://localhost:8501](http://localhost:8501)

   ```

5. **Введите запрос** на естественном языке, например:

   - `Покажи топ-5 исполнителей по количеству продаж`

   - `Какая страна принесла больше всего денег?`

   - `Сколько счетов было выставлено в 2023 году?`

Остановка проекта

Для остановки контейнеров (с сохранением данных):

```bash

docker-compose down

```

Для полной очистки (удаление БД, модели и всех данных):

```bash

docker-compose down -v

```

Повторный запуск

После первой загрузки модель сохраняется локально, поэтому повторные запуски быстрые:

```bash

docker-compose up

```

Ограничения текущей реализации

Технические ограничения

1. **Зависимость от размера модели**

   - Используется модель Qwen 2.5 Coder 7B (~4.5 ГБ)

   - Для очень сложных запросов (5+ JOIN, подзапросы) точность генерации SQL может снижаться

   - Решение: переключение на более мощные модели `qwen2.5-coder:14b`, `qwen2.5:32b`) при наличии ресурсов

2. **Отсутствие контекста диалога**

   - Агент обрабатывает каждый запрос изолированно (stateless)

   - Не запоминает предыдущие вопросы пользователя

   - Не поддерживает уточняющие вопросы в рамках сессии

3. **Ресурсоёмкость**

   - Требуется минимум 8 ГБ RAM для работы модели

   - Общий объём Docker-образов: ~6-7 ГБ

   - Первое скачивание модели занимает 5-15 минут



Функциональные ограничения

1. **Только SELECT-запросы** — невозможность выполнения INSERT, UPDATE, DELETE запрещены архитектурно

2. **Фиксированная схема** — агент работает только с предопределённой схемой Chinook

3. **Отсутствие визуализации** — результаты выводятся в текстовом виде и таблице, без графиков

4. **Ограничение результата** — максимум 20 строк для предотвращения перегрузки



Архитектурные ограничения

1. **Зависимость от Docker** — требуется установленный Docker Desktop

2. **Локальное развёртывание** — решение рассчитано на одного пользователя

3. **Нет горизонтального масштабирования** — один инстанс Ollama обслуживает одного пользователя
